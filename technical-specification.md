## 2. ОПИСАНИЕ ПРОЕКТА

### Название проекта
«Сервис бронирования помещений» (Room Booking Service)

### Назначение
Веб-приложение для автоматизации бронирования переговорных комнат, конференц-залов и служебных помещений в офисах и учебных заведениях. Позволяет сотрудникам просматривать свободные слоты и бронировать помещения, а администраторам — управлять перечнем помещений.

### Выявленные проблемы
- Отсутствие единой системы бронирования.
- Конфликты из-за двойного бронирования.
- Невозможность быстро оценить загруженность помещений.
- Потеря информации о бронях (бумажные записи, хаос в чатах).

### Решение
- Единая база помещений.
- Наглядное расписание (сетка времени).
- Бронирование в 3-4 клика.
- Личный кабинет с историей броней.
- Админ-панель для управления помещениями.

### Целевая аудитория

**Сотрудник** — Быстро найти и забронировать свободное помещение на нужное время

**Руководитель отдела** — Планировать встречи, видеть загруженность команды

**Администратор офиса** — Управлять помещениями, следить за порядком бронирований

### Решаемые задачи
1. Автоматизация процесса бронирования помещений.
2. Визуализация расписания и свободных слотов.
3. Предотвращение двойных броней.
4. Централизованное хранение информации о бронированиях.
   ## 3. ФОРМАЛИЗАЦИЯ ТРЕБОВАНИЙ

### 3.1 Функциональные требования

**Роль «Пользователь» (сотрудник):**

- **F01** — Авторизация: Вход в систему по логину/паролю
- **F02** — Просмотр помещений: Просмотр списка всех доступных помещений с фильтрацией по вместимости и оборудованию
- **F03** — Просмотр расписания: Просмотр календаря занятости помещений на день/неделю
- **F04** — Создание брони: Выбор времени и помещения, указание цели встречи → создание брони
- **F05** — Мои бронирования: Просмотр списка своих будущих и прошедших броней
- **F06** — Отмена брони: Отмена своего будущего бронирования

**Роль «Администратор»:**

- **A01** — Управление помещениями: Добавление, редактирование, удаление помещений
- **A02** — Управление бронями: Просмотр всех бронирований, отмена любой брони
- **A03** — Статистика: Просмотр статистики загруженности помещений

### 3.2 Нефункциональные требования

- **N01** — Производительность: Время загрузки страницы расписания ≤ 2 секунды
- **N02** — Надёжность: Предотвращение двойного бронирования (100% исключение конфликтов)
- **N03** — Доступность: Работа через браузер (Chrome, Firefox, Edge, Yandex)
- **N04** — Адаптивность: Корректное отображение на планшетах
- **N05** — Безопасность: Доступ только авторизованным пользователям
- **N06** — Интуитивность: Создание брони за ≤ 4 кликов

### 5.2 Описание таблиц

**Таблица: Users (Пользователи)**

- `id` — INTEGER — Уникальный идентификатор — PRIMARY KEY, AUTO_INCREMENT
- `email` — VARCHAR(100) — Электронная почта пользователя — UNIQUE, NOT NULL
- `passwordHash` — VARCHAR(255) — Хеш пароля — NOT NULL
- `fullName` — VARCHAR(100) — Полное имя — NOT NULL
- `role` — ENUM ('user'/'admin') — Роль — DEFAULT 'user'
- `createdAt` — TIMESTAMP — Дата регистрации — DEFAULT NOW()

**Таблица: Rooms (Помещения)**

- `id` — INTEGER — Уникальный идентификатор — PRIMARY KEY, AUTO_INCREMENT
- `name` — VARCHAR(50) — Название помещения — NOT NULL, UNIQUE
- `capacity` — INTEGER — Вместимость (человек) — NOT NULL, CHECK (>0)
- `hasProjector` — BOOLEAN — Наличие проектора — DEFAULT false
- `hasWhiteboard` — BOOLEAN — Наличие доски/флипчарта — DEFAULT false
- `description` — TEXT — Дополнительное описание
- `createdAt` — TIMESTAMP — Дата добавления — DEFAULT NOW()

**Таблица: Bookings (Бронирования)**

- `id` — INTEGER — Уникальный идентификатор — PRIMARY KEY, AUTO_INCREMENT
- `userId` — INTEGER — ID пользователя — FOREIGN KEY (Users.id)
- `roomId` — INTEGER — ID помещения — FOREIGN KEY (Rooms.id)
- `date` — DATE — Дата бронирования — NOT NULL
- `startTime` — TIME — Время начала — NOT NULL
- `endTime` — TIME — Время окончания — NOT NULL
- `purpose` — VARCHAR(200) — Цель встречи — NOT NULL
- `status` — ENUM ('active'/'cancelled') — Статус — DEFAULT 'active'
- `createdAt` — TIMESTAMP — Дата создания брони — DEFAULT NOW()

### 5.3 Ограничения целостности

1. **Проверка времени:** `endTime > startTime`
2. **Защита от двойного бронирования:** Нет пересечений броней для одной комнаты на одну дату и время
3. **Ссылочная целостность:** Нельзя создать бронь для несуществующего пользователя или помещения
4. **Уникальность:** Название помещения должно быть уникальным
   ## 6. ПРОЕКТИРОВАНИЕ API

### 6.1 REST API Endpoints

**Аутентификация**

- `POST /api/auth/login` — Вход в систему
  - Тело: `{"email": "user@mail.com", "password": "***"}`
  - Ответ: `{"token": "jwt_token", "user": {...}}`

- `POST /api/auth/logout` — Выход из системы
  - Ответ: `{"success": true}`

- `POST /api/auth/register` — Регистрация
  - Тело: `{"email": "...", "password": "...", "fullName": "..."}`
  - Ответ: `{"token": "...", "user": {...}}`

**Помещения (Rooms)**

- `GET /api/rooms` — Список помещений
  - Параметры: `?capacity=5&projector=true&whiteboard=true`
  - Ответ: Массив помещений

- `GET /api/rooms/:id` — Детали помещения
  - Ответ: Объект помещения

- `POST /api/rooms` — Создать помещение (admin)
  - Тело: `{"name": "Зал А", "capacity": 10, "hasProjector": true}`
  - Ответ: Созданное помещение

- `PUT /api/rooms/:id` — Обновить помещение (admin)
  - Тело: `{"capacity": 15, "hasWhiteboard": true}`
  - Ответ: Обновлённое помещение

- `DELETE /api/rooms/:id` — Удалить помещение (admin)
  - Ответ: `{"success": true}`

**Бронирования (Bookings)**

- `GET /api/bookings/my` — Мои бронирования
  - Ответ: Массив броней

- `GET /api/bookings` — Брони по параметрам
  - Параметры: `?roomId=5&date=2024-12-20`
  - Ответ: Массив броней

- `POST /api/bookings` — Создать бронь
  - Тело: `{"roomId": 5, "date": "2024-12-25", "startTime": "14:00", "endTime": "15:30", "purpose": "Совещание"}`
  - Ответ: Созданная бронь

- `DELETE /api/bookings/:id` — Отменить бронь
  - Ответ: `{"success": true}`

- `GET /api/bookings/availability` — Проверка доступности
  - Параметры: `?roomId=5&date=2024-12-25&startTime=14:00&endTime=15:30`
  - Ответ: `{"available": true}`
